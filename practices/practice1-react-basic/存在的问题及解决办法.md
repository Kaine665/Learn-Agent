# 实践1：最简 ReAct Agent - 存在的问题及解决办法

## 问题1：Token 重复消耗问题

### 问题描述

当前实现中存在严重的 token 重复消耗问题，导致不必要的 API 调用成本增加。

### 问题分析

#### 当前实现的问题

在每次迭代中，相同的内容会被重复发送多次：

**迭代 1 后的 conversation_history：**
```python
[
    {
        "role": "assistant", 
        "content": "Thought: 用户需要...\nAction: answer\nAction Input: 主要功能需求包括：1. 用户注册/登录；2. 账单录入..."  # 完整内容
    },
    {
        "role": "user",
        "content": "Observation: 回答：主要功能需求包括：1. 用户注册/登录；2. 账单录入..."  # 重复内容
    }
]
```

**迭代 2 时构建的 messages：**
```python
[
    {"role": "system", "content": "系统提示..."},
    {
        "role": "assistant", 
        "content": "Thought: ...\nAction: answer\nAction Input: 主要功能需求包括：1. 用户注册/登录..."  # ← 第一次出现
    },
    {
        "role": "user",
        "content": "Observation: 回答：主要功能需求包括：1. 用户注册/登录..."  # ← 第二次出现（重复！）
    },
    {
        "role": "user",
        "content": "用户查询：...\n\n观察结果：回答：主要功能需求包括：1. 用户注册/登录...\n\n请继续思考下一步行动。"  # ← 第三次出现（重复！）
    }
]
```

#### 重复的原因

1. **Assistant 输出包含完整 Action Input**：LLM 输出的完整内容被保存到 `conversation_history`
2. **Observation 重复 Action Input**：对于 `answer` 操作，`observation = f"回答：{action_input}"`，完全重复了 Action Input 的内容
3. **新的 User Message 再次包含 Observation**：在 `_think` 方法中，observation 又被添加到新的 user message 中

#### Token 消耗估算

假设每次迭代的 Action Input 长度为 1500 字符：

**优化前（10 次迭代）：**
- 每次迭代：完整 output (1500) + observation (1500) + 新 user message (1500) = 约 4500 tokens
- 10 次迭代累积：约 **45,000 tokens**

**优化后：**
- 每次迭代：精简 output (300) + 简短 observation (50) + 新 user message (100) = 约 450 tokens
- 10 次迭代累积：约 **4,500 tokens**

**节省比例：约 90%**

### 解决方案

#### 方案 1：精简历史记录（推荐）

只保存关键信息，不保存完整的 Action Input：

```python
# 在 _think 方法中（第 136-145 行）
output = response.choices[0].message.content
parsed = self._parse_llm_output(output)

# 优化：只保存精简的历史，避免重复的长内容
action_input_summary = parsed["action_input"]
if action_input_summary and len(action_input_summary) > 300:
    # 长内容只保存前100字符 + 摘要标记
    action_input_summary = action_input_summary[:100] + f"\n... [省略 {len(action_input_summary) - 100} 字符] ..."

simplified_output = f"Thought: {parsed['thought']}\nAction: {parsed['action']}"
if action_input_summary:
    simplified_output += f"\nAction Input: {action_input_summary}"

self.conversation_history.append({
    "role": "assistant",
    "content": simplified_output  # 保存精简版本，而不是完整 output
})

return parsed
```

#### 方案 2：避免重复发送 Observation

如果 observation 与 action_input 相同（如 answer 操作），不重复发送：

```python
# 在 run 方法中（第 215-219 行）
# 记录观察结果到历史
# 优化：如果 observation 只是重复 action_input（answer 操作），只保存简短标记
if action == "answer" and observation == f"回答：{action_input}":
    # 不重复保存完整内容，只保存标记
    self.conversation_history.append({
        "role": "user",
        "content": "Observation: 已回答（内容见上一步 Action Input）"
    })
else:
    # 其他情况正常保存（如 calculate 的结果）
    self.conversation_history.append({
        "role": "user",
        "content": f"Observation: {observation}"
    })
```

#### 方案 3：优化 User Message 构建

在 `_think` 方法中，如果 observation 只是标记，不重复发送完整内容：

```python
# 在 _think 方法中（第 108-112 行）
# 添加当前查询和观察
if observation:
    # 优化：如果 observation 只是标记，不重复发送完整内容
    if observation == "已回答（内容见上一步 Action Input）":
        messages.append({
            "role": "user",
            "content": f"用户查询：{user_query}\n\n上一步行动已完成。请继续思考下一步行动。"
        })
    else:
        messages.append({
            "role": "user",
            "content": f"用户查询：{user_query}\n\n观察结果：{observation}\n\n请继续思考下一步行动。"
        })
else:
    messages.append({
        "role": "user",
        "content": f"用户查询：{user_query}\n\n请开始思考和行动。"
    })
```

### 推荐实现

**组合使用方案 1 + 方案 2 + 方案 3**，可以最大程度减少 token 消耗：

1. **精简 Assistant 输出**：只保存 Thought 和 Action，Action Input 超过 300 字符时只保存摘要
2. **精简 Observation**：对于 `answer` 操作，只保存简短标记，不重复完整内容
3. **优化 User Message**：根据 observation 的类型，决定是否包含完整内容

### 注意事项

1. **保留完整信息用于调试**：虽然历史中保存的是精简版本，但 `parsed` 返回的仍是完整信息，可用于打印和调试
2. **不影响功能**：LLM 仍能看到必要的上下文（Thought + Action），只是不重复长内容
3. **特殊情况处理**：对于 `calculate` 等操作，observation 是计算结果，仍需完整保存

### 实施建议

1. **立即实施**：这个问题会导致大量不必要的成本，建议尽快优化
2. **测试验证**：优化后需要测试 Agent 的功能是否正常，确保 LLM 仍能正确理解上下文
3. **监控成本**：实施后可以对比优化前后的 token 使用量，验证优化效果
