# ReAct Agent 上下文优化思考

## 核心洞察

**当前直接堆砌上下文的方式，实际上对思考是个阻碍。**

## 当前方式的问题

### 问题1：信息过载

当前实现中，每次迭代都会把所有历史完整地发送给 LLM：

```python
# 第10次迭代时，LLM 看到的是：
messages = [
    System Prompt,
    Assistant: "Thought: ... Action: answer Action Input: [1500字符的功能需求]",
    User: "Observation: 回答：[1500字符重复内容]",
    Assistant: "Thought: ... Action: answer Action Input: [2000字符的架构设计]",
    User: "Observation: 回答：[2000字符重复内容]",
    Assistant: "Thought: ... Action: answer Action Input: [3000字符的代码]",
    User: "Observation: 回答：[3000字符重复内容]",
    # ... 还有7次迭代的历史
    User: "用户查询：... 观察结果：..."
]
```

**问题：**
- ❌ 大量重复内容（Action Input 和 Observation 重复）
- ❌ 历史越来越长，LLM 需要从大量文本中提取关键信息
- ❌ Token 消耗巨大
- ❌ LLM 可能被历史信息干扰，难以聚焦当前任务

### 问题2：缺乏结构化

当前方式像"把所有东西堆在一起"：

```python
历史 = [
    "第1步的完整输出",
    "第1步的观察结果",
    "第2步的完整输出",
    "第2步的观察结果",
    ...
]
```

**问题：**
- ❌ 没有结构化的信息组织
- ❌ LLM 需要自己从文本中提取关键信息
- ❌ 无法快速定位"我做了什么决策""关键信息是什么"

### 问题3：噪音干扰

对于长任务，历史中可能包含：
- 大量重复的代码
- 已经完成的步骤
- 不相关的中间结果

这些信息对当前思考可能是**噪音**，而不是有用的上下文。

---

## 改进方案

### 方案1：摘要式记忆（Summary Memory）

只保留关键信息，不保留完整内容：

```python
def _think(self, user_query: str, observation: Optional[str] = None):
    # 构建消息历史
    messages = [
        {"role": "system", "content": self._build_system_prompt()}
    ]
    
    # 优化：只保留关键信息摘要
    if self.conversation_history:
        # 提取关键决策点
        summary = self._summarize_history()
        messages.append({
            "role": "user",
            "content": f"之前的执行摘要：\n{summary}"
        })
    
    # 只保留最近1-2步的完整上下文（短期记忆）
    recent_history = self.conversation_history[-2:] if len(self.conversation_history) > 2 else self.conversation_history
    for entry in recent_history:
        messages.append(entry)
    
    # 添加当前查询和观察
    # ...
```

**优点：**
- ✅ 减少 token 消耗
- ✅ 保留关键信息
- ✅ 减少噪音干扰

### 方案2：结构化记忆（Structured Memory）

用结构化方式组织信息，而不是堆砌文本：

```python
class StructuredMemory:
    def __init__(self):
        self.decisions = []  # 关键决策
        self.results = []    # 关键结果
        self.current_step = None  # 当前步骤
    
    def add_step(self, thought, action, result_summary):
        """只保存关键信息"""
        self.decisions.append({
            "step": len(self.decisions) + 1,
            "thought": thought[:200],  # 只保留思考要点
            "action": action,
            "result": result_summary[:200]  # 只保留结果摘要
        })
    
    def to_prompt(self):
        """转换为 prompt 格式"""
        summary = "执行历史：\n"
        for decision in self.decisions[-3:]:  # 只保留最近3步
            summary += f"步骤{decision['step']}: {decision['thought']} → {decision['action']} → {decision['result']}\n"
        return summary
```

**优点：**
- ✅ 信息结构化，易于理解
- ✅ 只保留关键信息
- ✅ 可以快速定位决策点

### 方案3：分层记忆（Hierarchical Memory）

区分短期记忆和长期记忆：

```python
class HierarchicalMemory:
    def __init__(self):
        self.short_term = []  # 短期记忆：最近2-3步
        self.long_term = []   # 长期记忆：关键决策点
    
    def add(self, thought, action, result):
        # 添加到短期记忆
        self.short_term.append({
            "thought": thought,
            "action": action,
            "result": result
        })
        
        # 如果这一步是关键决策，也添加到长期记忆
        if self._is_key_decision(action, result):
            self.long_term.append({
                "thought": thought[:100],  # 摘要
                "action": action,
                "result": result[:100]  # 摘要
            })
        
        # 保持短期记忆不超过3步
        if len(self.short_term) > 3:
            self.short_term.pop(0)
    
    def to_prompt(self):
        """构建 prompt"""
        prompt = ""
        if self.long_term:
            prompt += f"关键决策历史：\n{self._format_long_term()}\n\n"
        prompt += f"最近步骤：\n{self._format_short_term()}"
        return prompt
```

**优点：**
- ✅ 区分短期和长期记忆
- ✅ 短期记忆保持详细，长期记忆保持摘要
- ✅ 更符合人类记忆机制

### 方案4：任务状态追踪（Task State Tracking）

不保存完整历史，只追踪任务状态：

```python
class TaskState:
    def __init__(self, user_query):
        self.user_query = user_query
        self.completed_steps = []  # 已完成的关键步骤
        self.current_focus = None   # 当前关注点
        self.next_steps = []        # 下一步计划
    
    def add_completed_step(self, step_name, summary):
        """记录完成的步骤"""
        self.completed_steps.append({
            "step": step_name,
            "summary": summary[:100]  # 只保留摘要
        })
    
    def to_prompt(self):
        """转换为 prompt"""
        prompt = f"用户目标：{self.user_query}\n\n"
        prompt += "已完成：\n"
        for step in self.completed_steps:
            prompt += f"- {step['step']}: {step['summary']}\n"
        prompt += f"\n当前关注：{self.current_focus}"
        return prompt
```

**优点：**
- ✅ 只追踪任务状态，不保存完整历史
- ✅ 清晰的任务进度
- ✅ 最小化 token 消耗

## 推荐方案：组合使用

结合多种方式，既保留必要上下文，又避免信息过载：

```python
def _think(self, user_query: str, observation: Optional[str] = None):
    messages = [
        {"role": "system", "content": self._build_system_prompt()}
    ]
    
    # 1. 任务状态摘要（如果有）
    if hasattr(self, 'task_state') and self.task_state:
        messages.append({
            "role": "user",
            "content": f"任务状态：\n{self.task_state.to_summary()}"
        })
    
    # 2. 只保留最近1-2步的完整上下文（短期记忆）
    recent_steps = self.conversation_history[-2:] if len(self.conversation_history) > 2 else []
    for entry in recent_steps:
        # 精简版本：只保留 Thought 和 Action，不保留完整 Action Input
        simplified = self._simplify_entry(entry)

    messages.append({
        "role": "user",
        "content": f"用户查询：{user_query}\n\n观察结果：{observation}\n\n请继续思考下一步行动。"
    })
```

## 核心思想

### 当前方式的问题

**直接堆砌上下文 = 把所有东西堆在一起**
- 信息过载
- 缺乏结构
- 噪音干扰
- Token 浪费

### 优化方向

**结构化、摘要化、分层化**

1. **摘要而非完整**：只保留关键信息
2. **结构化而非堆砌**：用结构组织信息
3. **分层而非平铺**：区分短期/长期记忆
4. **聚焦而非全量**：只保留对当前思考有用的信息

### 优化后的效果

LLM 可以：
- ✅ 更快定位关键信息
- ✅ 减少噪音干扰
- ✅ 更聚焦当前任务
- ✅ 节省 token（可能节省 70-90%）

---

## 实施建议

1. **立即优化**：先实现方案1（摘要式记忆），最简单有效
2. **逐步改进**：根据实际效果，考虑引入方案2或方案3
3. **监控效果**：对比优化前后的 token 消耗和任务完成质量
4. **平衡取舍**：在"保留足够上下文"和"减少信息过载"之间找到平衡

---

## 总结

**核心洞察：直接堆砌上下文会阻碍思考**

当前 ReAct Agent 的实现虽然简单有效，但在处理长任务时，上下文堆砌会导致：
- 信息过载
- Token 浪费
- 思考效率下降

**解决方案：**
- 摘要式记忆
- 结构化记忆
- 分层记忆
- 任务状态追踪

通过这些优化，可以让 Agent 在保持上下文连贯性的同时，提高思考效率，减少 token 消耗。
