# Plan Agent 问题诊断与改进思路

## 核心问题

> **这个 plan agent 在"信息组织"上是成功的，在"决策与约束"上是失败的。**
> 
> 它更像一个"自动写提纲 + 自动扩写器"，而不是一个真正帮你**降低认知成本、提高确定性**的规划器。

---

## 一、它【确实】起到的作用（但不显眼）

### 1️⃣ 它完成了「结构化外包」

如果你**不用 plan agent**，你需要自己决定：

- 从哪一年开始？
- 要不要分阶段？
- 要不要列人物 / 技术 / 伦理？
- 是时间线写，还是主题写？

👉 这些"决策成本"被 agent **自动做掉了**。

**它帮你完成的是：**

> "把一个模糊的大问题，展开成一条教科书级的、可交付的完整叙事。"

这在**写作 / 综述 / 作业 / 报告**场景里是合格的。

### 2️⃣ 它保证了「不遗漏常识性关键节点」

对照一下：

- 图灵 ✔
- 达特茅斯 ✔
- 感知机 ✔
- 两次寒冬 ✔
- 反向传播 ✔
- AlexNet ✔
- AlphaGo ✔
- Transformer / ChatGPT ✔

👉 **一个都没漏**，也没明显胡编。

这说明：它在做的是一个 **"标准答案生成器"**。

---

## 二、但你真正困惑的点在这里（核心问题）

你不是在问：

> "这份内容对不对？"

你在问的是：

> **"我为什么要用 plan agent？
> 它和我直接让 AI 写一篇《人工智能发展史》有什么本质区别？"**

👉 **答案是：现在这个版本，几乎没有本质区别。**

---

## 三、它【没有】起到的关键作用（也是你不爽的根源）

### ❌ 1️⃣ 规划 ≠ 列步骤

你现在的 plan agent 本质在做：

```
步骤 1：说我要干嘛
步骤 2：列资料
步骤 3：按时间写
步骤 4：列里程碑
步骤 5：扩写
步骤 6：总结
步骤 7：再总结一次
```

但**真正的规划 agent**应该回答的是：

- ❓ 我现在为什么要做这个？
- ❓ 哪一步是**可以省略的**？
- ❓ 哪一步是**必须人工介入判断的**？
- ❓ 什么时候该停？

你这个 plan agent **从头到尾没有做任何取舍**。

👉 所以你会有一种感觉：

> "它好像很认真，但我好像被它拖着走。"

### ❌ 2️⃣ 没有「成功判据」（Success Criteria）

这是最致命的一点。

整个流程里，从未出现一句类似：

- ✅ 如果目标是【教学】，做到 X 就够了
- ✅ 如果目标是【研究综述】，要额外 Y
- ❌ 如果只是【了解历史】，步骤 4 以后都是冗余

所以你现在：

- 看到了 7 步
- 得到了 8000+ 字
- **但不知道：哪一步对你真正有价值**

👉 **没有"完成定义"的计划，一定会显得又长又空。**

### ❌ 3️⃣ 没有"你的位置"

整个 plan agent 的输出是：

> "人工智能发展史（客观完整版）"

而不是：

- "**给一个 AI 初学者** 的 30 分钟版本"
- "**给产品经理** 的认知地图"
- "**给做系统架构的人** 的技术路线演化"
- "**给你** 的版本"

👉 它**没把你当变量**。

所以你才会觉得：

> "这东西我看完，好像也没更清楚该怎么用它。"

---

## 四、为什么你会"无法判定规划是否起作用"

给你一句非常关键的话（你可能会记住）：

> **如果一个 plan 的每一步，都可以被一句「那我直接让 AI 写不就好了？」替代——
> 那这个 plan 就不是 plan，而是"慢速生成"。**

你这个流程里：

- 步骤 1 ❓ → 直接一句 prompt 能做
- 步骤 2 ❓ → AI 自动会列
- 步骤 3~7 ❓ → AI 一次性全写完

👉 **没有一步是"非拆不可"的**。

---

## 五、那什么样的 plan agent 才「真的值」？

我直接给你一个**可落地的判断标准**，以后你一眼就能看出来👇

### ✅ 一个有效的 plan agent，至少要做到 3 件事之一

#### 1️⃣ 帮你 **删掉 50% 本不该做的内容**

例如它会说：

> "如果你的目标只是理解 AI 技术演化逻辑，
> 步骤 2 的书籍列表、步骤 4 的完整里程碑表可以跳过。"

#### 2️⃣ 强迫你在关键点做选择

例如：

> "请选择你更关心哪一条主线：
> A. 学术方法论
> B. 工程/产业落地
> C. 社会与伦理影响
> 我将只展开一条，其余只保留索引。"

#### 3️⃣ 给出「到此为止」的明确标志

例如：

> "当你能用 3 句话解释：
> 为什么 AI 在 2010 年后突然爆发，
> 这个任务就完成了。"

## 六、你现在这套 plan agent，我会怎么评价

很直接，但我觉得你能接受：

> **这是一个"内容型 agent"，不是"决策型 agent"。
> 它擅长把事情做完，但不擅长判断事情值不值得做。**

所以你才会：

- 没法判定"规划是否成功"
- 没法衡量"有没有帮我省时间"
- 没法复用这套 plan 到下一个问题

---

## 七、改进方向

### 当前实现的问题本质

这不是 Plan-and-Execute 模式的问题，而是当前实现缺少"规划智能"：

1. **规划阶段缺少约束和目标**
   - 没有用户画像（给谁看）
   - 没有成功标准（什么时候算完成）
   - 没有资源限制（时间/成本/质量）

2. **执行阶段缺少反馈循环**
   - 没有"提前完成"判断
   - 没有"步骤冗余"检测
   - 没有"质量检查"机制

### 改进方案（3 选 1）

#### 选项 1：增强规划阶段（推荐）

在规划 prompt 中加入：

```python
def _build_planning_prompt(self, goal: str, user_context: Optional[str] = None) -> str:
    return f"""你是一个任务规划专家。用户给你一个目标，你需要：
1. **先判断任务类型和用户需求**
2. **生成最小必要步骤**（能省略的步骤要明确标注）
3. **定义成功标准**（什么时候算完成）

目标：{goal}
用户上下文：{user_context or "未提供"}

请先回答：
- 这个任务的目标用户是谁？（初学者/专家/产品经理等）
- 这个任务的核心价值是什么？（理解概念/做决策/写报告等）
- 最少需要几步？（哪些步骤可以合并或省略）

然后生成计划：
计划：
1. [必需步骤1] - 原因：xxx
2. [必需步骤2] - 原因：xxx
3. [可选步骤3] - 原因：xxx（如果时间充足）

成功标准：
- 当用户能够 [具体可验证的目标] 时，任务完成
"""
```

#### 选项 2：增加执行阶段的智能判断

在执行每个步骤后，判断：
- 是否已经达到成功标准
- 后续步骤是否还有必要
- 是否需要调整计划

#### 选项 3：设计"反规划版本"

一个 prompt 完成真正有价值的 20%，直接给出核心结果，跳过冗余步骤。

## 八、关键判断标准

### 如何判断 Plan Agent 是否有效？

**核心标准：**

> **如果一个 plan 的每一步，都可以被一句「那我直接让 AI 写不就好了？」替代——
> 那这个 plan 就不是 plan，而是"慢速生成"。**

### 有效 Plan Agent 的特征

1. ✅ **有取舍**：明确哪些步骤是必需的，哪些是可选的
2. ✅ **有目标**：定义"完成"的标准，而不是"做完所有步骤"
3. ✅ **有用户**：考虑用户画像和使用场景
4. ✅ **有反馈**：在执行过程中判断是否需要调整或提前终止

### 无效 Plan Agent 的特征

1. ❌ **无脑分解**：只是把任务拆成步骤，不做任何判断
2. ❌ **全部执行**：不管是否必要，所有步骤都要执行完
3. ❌ **无成功标准**：不知道什么时候算"完成"
4. ❌ **无用户意识**：不考虑用户是谁、需要什么

## 九、总结

### 核心洞察

**内容型 Agent vs 决策型 Agent**

- **内容型 Agent**（当前实现）：
  - 擅长：把事情做完、生成完整内容
  - 不擅长：判断值不值得做、做取舍、优化效率

- **决策型 Agent**（应该的方向）：
  - 擅长：做决策、判断价值、优化路径
  - 目标：降低认知成本、提高确定性

### 改进方向

优先选择**增强规划阶段**，因为：

1. 从源头解决问题
2. 改动相对集中
3. 能直接体现"规划智能"

### 实践建议

1. **明确用户画像**：规划时考虑"给谁看"
2. **定义成功标准**：明确"什么时候算完成"
3. **做取舍判断**：区分必需步骤和可选步骤
4. **增加反馈循环**：执行过程中判断是否需要调整

## 十、参考：实践中的改进示例

### 改进前（当前实现）

```
目标：分析人工智能发展历史

计划：
1. 收集相关资料
2. 整理时间线
3. 列出里程碑
4. 详细描述每个里程碑
5. 总结趋势
6. 输出报告
```

**问题：**
- 没有考虑用户需求
- 没有定义完成标准
- 所有步骤都是必需的（没有取舍）

### 改进后（理想实现）

```
目标：分析人工智能发展历史

用户画像：AI 初学者，想快速了解技术演化逻辑
核心价值：理解 AI 技术发展的关键转折点

计划：
1. [必需] 识别关键转折点（图灵、达特茅斯、两次寒冬、深度学习、大模型）
   - 原因：这是理解技术演化的核心
2. [必需] 解释每个转折点的技术原因
   - 原因：帮助理解"为什么"而不是"是什么"
3. [可选] 详细列出所有里程碑
   - 原因：如果只需要理解主线，可以跳过
4. [必需] 总结技术演化的逻辑
   - 原因：这是最终目标

成功标准：
- 当用户能够解释"为什么 AI 在 2010 年后突然爆发"时，任务完成
- 如果用户只需要主线理解，步骤 3 可以跳过
```

**改进点：**
- ✅ 有用户画像
- ✅ 有成功标准
- ✅ 有步骤取舍
- ✅ 有完成判断

## 附录：代码层面的具体问题

### 问题 1：规划 Prompt 缺少约束

当前实现（`_build_planning_prompt`）只要求"分解"，没有要求：
- 判断哪些步骤是必需的
- 考虑用户的使用场景
- 定义"完成"的标准

### 问题 2：执行阶段缺少反馈循环

当前实现（`execute` 方法）只是机械地执行所有步骤，没有：
- 中途判断"是否已经足够"
- 根据执行结果调整后续步骤
- 提前终止机制

### 问题 3：没有用户上下文

整个流程中，没有考虑：
- 用户是谁（初学者/专家/产品经理）
- 用户需要什么（理解概念/做决策/写报告）
- 用户的资源限制（时间/成本/质量要求）
