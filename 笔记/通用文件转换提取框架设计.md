# 通用文件转换提取框架设计

## 核心思想

**从硬编码的格式解析，转向智能的、可学习的转换规则系统。**

### 问题背景

在实际应用中，我们经常需要处理各种格式的文件：
- 微信支付账单（Excel，有元数据+结构化数据）
- 支付宝账单（Excel，不同结构）
- 银行流水（CSV，不同格式）
- 其他第三方数据源

传统方式的问题：
- ❌ 每种格式都需要硬编码解析逻辑
- ❌ 格式变化时需要修改代码
- ❌ 无法处理未知格式
- ❌ 解析错误难以发现和修复

### 设计目标

1. **智能识别**：AI自动识别文件格式和结构
2. **自信度评估**：AI评估自己能否100%准确提取数据
3. **交互式学习**：无法确定时，与用户讨论并学习
4. **规则持久化**：将转换规则保存，后续直接复用
5. **格式无关**：支持任意格式的文件转换

## 架构设计

### 核心组件

```
文件转换系统
├── FormatDetector（格式检测器）
│   ├── 识别文件类型（Excel/CSV/JSON等）
│   ├── 识别数据源类型（微信/支付宝/银行等）
│   └── 检测文件结构（元数据区域、表头位置等）
│
├── DataExtractor（数据提取器）
│   ├── 自动提取（AI尝试自动提取）
│   ├── 自信度评估（评估提取准确性）
│   └── 提取结果验证
│
├── RuleManager（规则管理器）
│   ├── 规则存储（保存转换规则）
│   ├── 规则匹配（匹配已有规则）
│   └── 规则应用（应用规则提取数据）
│
├── InteractiveLearner（交互式学习器）
│   ├── 问题识别（识别无法确定的部分）
│   ├── 用户交互（与用户讨论）
│   └── 规则生成（生成新的转换规则）
│
└── TargetSchema（目标数据模型）
    └── 定义目标数据结构
```

## 工作流程

### 阶段1：格式检测与规则匹配

```
用户上传文件
    ↓
FormatDetector检测文件格式
    ↓
RuleManager查找匹配的转换规则
    ↓
找到规则？
    ├─ 是 → 直接应用规则提取数据
    └─ 否 → 进入阶段2
```

### 阶段2：自动提取与自信度评估

```
未找到规则
    ↓
DataExtractor尝试自动提取
    ├─ 识别元数据区域
    ├─ 识别表头位置
    ├─ 建立列映射关系
    └─ 提取数据行
    ↓
自信度评估
    ├─ 100%确定 → 提取成功，保存规则
    ├─ 部分不确定 → 进入阶段3
    └─ 无法处理 → 进入阶段3
```

### 阶段3：交互式学习

```
AI无法确定
    ↓
InteractiveLearner识别问题
    ├─ 问题1：无法确定表头位置
    ├─ 问题2：无法确定列映射关系
    ├─ 问题3：无法判断收入/支出
    └─ 问题4：无法解析某些字段
    ↓
与用户交互讨论
    ├─ 展示原始数据结构
    ├─ 说明目标数据结构
    ├─ 询问用户确认
    └─ 获取用户指导
    ↓
生成转换规则
    ├─ 记录格式特征
    ├─ 记录映射关系
    ├─ 记录解析逻辑
    └─ 保存规则到RuleManager
```

## 转换规则结构

### 规则定义

```python
class ConversionRule:
    """转换规则"""
    
    def __init__(self):
        # 规则标识
        self.rule_id: str  # 唯一标识
        self.source_type: str  # 数据源类型（如"微信支付账单"）
        self.file_format: str  # 文件格式（如"xlsx"）
        
        # 格式特征（用于匹配）
        self.format_signatures: List[str]  # 格式特征签名
        # 例如：["包含'微信支付账单明细'", "表头在第10行", "有'收/支'列"]
        
        # 结构映射
        self.structure_mapping: Dict[str, Any]
        # {
        #     "header_row": 10,  # 表头行号
        #     "metadata_patterns": ["微信支付账单明细", "起始时间"],  # 元数据模式
        #     "column_mapping": {  # 列映射
        #         "date": {"column": "交易时间", "index": 0},
        #         "amount": {"column": "收/支金额", "index": 1},
        #         "income_expense": {"column": "收/支", "index": 2},
        #         ...
        #     }
        # }
        
        # 数据转换逻辑
        self.transformation_logic: Dict[str, Callable]
        # {
        #     "is_income": lambda row, mapping: ...,  # 判断收入/支出的逻辑
        #     "parse_date": lambda value: ...,  # 日期解析逻辑
        #     "parse_amount": lambda value: ...,  # 金额解析逻辑
        #     ...
        # }
        
        # 验证规则
        self.validation_rules: List[Callable]
        # 用于验证提取的数据是否正确
        
        # 元数据
        self.created_at: datetime
        self.updated_at: datetime
        self.usage_count: int  # 使用次数
        self.success_rate: float  # 成功率
```

## 交互式学习机制

### 问题识别

AI需要识别以下类型的问题：

1. **结构识别问题**
   - "无法确定表头在第几行"
   - "无法区分元数据区域和数据区域"

2. **列映射问题**
   - "无法确定哪一列是日期"
   - "无法确定哪一列是金额"
   - "无法确定哪一列表示收入/支出"

3. **数据解析问题**
   - "无法判断这是收入还是支出"
   - "无法解析日期格式"
   - "无法提取某个字段的值"

4. **格式变化问题**
   - "文件格式与已知规则不匹配"
   - "列名发生了变化"

### 交互流程

```
AI识别问题
    ↓
展示给用户
    ├─ 原始数据结构（截图/示例）
    ├─ 目标数据结构（说明）
    └─ 具体问题（无法确定的部分）
    ↓
用户提供指导
    ├─ 确认表头位置
    ├─ 确认列映射关系
    ├─ 提供解析规则
    └─ 提供示例数据
    ↓
AI生成规则
    ├─ 记录用户指导
    ├─ 生成转换逻辑
    └─ 验证规则有效性
    ↓
保存规则
    └─ 供后续使用
```

## 使用场景示例

### 场景1：首次导入微信支付账单

```
1. 用户上传"微信支付账单流水.xlsx"
2. FormatDetector检测：Excel格式，疑似微信支付账单
3. RuleManager查找：未找到匹配规则
4. DataExtractor自动提取：部分不确定（无法确定收入/支出判断逻辑）
5. InteractiveLearner与用户讨论：确认转换规则
6. 生成并保存规则：wechat_payment_bill_v1
7. 提取数据成功
```

### 场景2：再次导入微信支付账单

```

3. RuleManager查找：找到规则 wechat_payment_bill_v1（匹配度100%）
4. DataExtractor直接应用规则提取
5. 提取成功，无需用户交互
```


## 优势总结

### 1. 智能化
- AI自动识别格式和结构
- 自动建立映射关系
- 自动评估提取准确性

### 2. 可学习
- 遇到未知格式时，通过交互学习
- 学习结果持久化保存
- 后续直接复用

### 3. 可扩展
- 支持任意格式的文件
- 规则可以不断积累
- 系统越来越智能

### 4. 可维护
- 规则独立于代码
- 格式变化只需更新规则
- 不需要修改核心代码

### 5. 用户友好
- 自动处理已知格式
- 未知格式时引导用户
- 学习一次，永久使用
