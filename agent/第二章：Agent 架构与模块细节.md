# 第二章：Agent 架构与模块细节

## 本章重点

拆解 Agent 的四大核心模块：

**感知 → 决策 → 执行 → 记忆**

并解释它们如何协同工作，形成一个完整的智能行动系统。

这一章是整个 Agent 系统的"骨架"，理解后你就能设计、评估甚至构建自己的 Agent。

---

## 2.1 Agent 的总体架构（全局图）

下面是一个标准 AI Agent 的信息流模型：

```
用户/环境输入
        │
        ▼
┌────────────────────┐
│ 感知 Perception     │ ← 解析输入、理解上下文
└──────────┬─────────┘
           │
           ▼
┌────────────────────┐
│ 决策 Decision       │ ← 推理、规划、选择行动
│（Agent 核心）       │
└──────────┬─────────┘
           │
           ▼
┌────────────────────┐
│ 执行 Action         │ ← 调用工具/生成输出
└──────────┬─────────┘
           │
           ▼
┌────────────────────┐
│ 记忆 Memory         │ ← 存储经验、检索上下文
└────────────────────┘
```

四个模块形成一个闭环，使 Agent 能够持续感知世界、思考、行动并学习。

---

## 2.2 感知模块（Perception）

感知模块承担的任务是理解输入、识别意图、解析环境信息。

### 感知模块的关键能力

#### 1）输入解析

包括：

- 用户指令（自然语言）
- 外部环境状态（API 返回、工具结果）
- 历史上下文

Agent 要能判断：

这是问题？请求？命令？补充信息？

#### 2）意图识别（Intent Detection）

**例如：**

用户说"帮我找一下今年的行业报告"，

感知模块要识别：

- **目标：** 找到某行业报告
- **参数：** 今年
- **任务：** 信息获取

#### 3）环境感知（Environment State）

包括：

- 工具状态（API 报错？返回格式？）
- 环境变化（文件是否更新？网页是否可访问？）

感知决定 Agent 是否要改变策略。

---

## 2.3 决策模块（Decision Making）——Agent 的大脑

决策模块是 AI Agent 的核心，它决定"下一步要做什么"。

### 决策一般包括三步

#### 1）推理（Reasoning）

理解问题本质、拆解任务。

**框架示例：**

- ReAct（Reason + Act）
- Chain-of-Thought 推理
- Tree-of-Thought 发散推理

#### 2）规划（Planning）

把目标拆成步骤（Action Plan），例如：

**目标：** 调研某行业市场规模  

**计划：**  
1. 搜索公开数据  
2. 匹配有价值来源  
3. 整理结构化信息  
4. 输出报告

规划让 Agent 能执行长任务。

#### 3）选择行动（Action Selection）

基于当前状态决定：

- 是否需要调用工具？
- 调用哪个工具？
- 如果工具失败，要不要改用其他方法？

这是 Agent 的"策略核心"。

### 决策模块的三种典型模式

#### 模式 1：ReAct（推理 + 行动循环）

**流程：**

```
Thought → Action → Observation → Thought → Action → ...
```

**特点：**

- 灵活
- 强适应性
- 易处理未知情况

**缺点：**

- 无整体规划
- 长任务可能不稳定

#### 模式 2：Plan-and-Execute（规划后执行）

**流程：**

```
Plan → Execute Steps → Output
```

**优点：**

- 稳定
- 可控
- 适合长任务（如制作一篇论文）

**缺点：**

- 计划可能需要动态调整

#### 模式 3：Mixed Initiative（混合策略）

系统允许 Agent：

- 先做计划
- 再按需调整步骤
- 工具失败时自动重构计划

现代 Agent（如现代 Copilot / OpenAI Agent API）一般都是这种。

---

## 2.4 执行模块（Action）——Agent 的身体

执行模块负责实际行动，而不是仅仅"说话"。

### 核心能力

#### 1）工具调用（Tool Use）

工具可以是：

- 搜索引擎
- 数据库查询
- 计算函数
- 文件系统
- 模型调用（例如图像识别模型）
- API（如天气查询、交易系统、自动化平台）

工具是 Agent 的"外部手臂"。

#### 2）动作执行（Action Execution）

**例如：**

- 阅读网页
- 生成代码
- 操作电脑（如浏览器自动化）
- 与其他 Agent 对话（Multi-Agent）

#### 3）错误恢复（Error Recovery）

工具失败时，Agent 要自动判断：

- 重试？
- 使用替代方案？
- 调整策略？
- 更新计划？

这是如今 Agent 的成熟度关键。

---

## 2.5 记忆模块（Memory）——Agent 的经验库

记忆模块分三类：

### 1）短期记忆（STM）

**范围：**

- 当前对话上下文
- 当前任务的状态
- 工具调用历史

**特点：**

- 临时
- 任务结束后通常清空

### 2）长期记忆（LTM）

存储可长期复用的信息：

- 用户偏好
- 历史项目资料
- 任务长期状态
- Agent 的知识
- 外部文件内容

长期记忆使 Agent 能做：

- 个性化任务
- 长期项目协作
- "持续任务"执行（如每周报告）

### 3）检索增强（RAG Memory）

从外部知识库中检索相关信息，提升决策能力。

**例：**

- ElasticSearch
- 向量数据库（Faiss, Milvus, Chroma）

记忆让 Agent 从"聊天机器人"进化到"多轮智能体"。

---

## 2.6 四大模块如何协同工作（循环机制）

完整的 Agent 循环如下：

```
Perceive → Reason → Plan → Act → Observe → Update Memory → Repeat
```

每一轮都比上一轮更有信息、更精准。

### 例如处理"帮我写一个市场报告"的流程：

1. **感知：** 理解任务与约束
2. **决策：** 规划查询、整理、输出步骤
3. **执行：** 工具搜索、阅读、提取信息
4. **观察：** 分析结果是否满足要求
5. **记忆：** 存储相关资料
6. **循环，** 交付更高质量成果

这就是 Agent 的闭环。
